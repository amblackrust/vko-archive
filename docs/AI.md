# ИИ на сайте Госархива ВКО

Всё ИИ — локальное: Ollama (`OLLAMA_URL`, по умолчанию `http://localhost:11434`), данные никуда не уходят.
ИИ — надстройка: без Ollama сайт, поиск и каталог работают, ИИ-блоки показывают «ИИ временно недоступен».

## Модели и параметры

| Что | Модель | Где |
|---|---|---|
| Ответы, разбор запроса | `OLLAMA_MODEL=qwen3.5:9b-q6k`, запасная `OLLAMA_FALLBACK_MODEL=qwen3.5:9b-q4_K_M` (выбирается сама, если основной нет) | `app/ai/ollama_client.py` |
| Векторы (поиск, рекомендации) | `OLLAMA_EMBED_MODEL=bge-m3`, 1024 измерения | `app/ai/embeddings.py`, `search_entries.embedding` |

Во всех вызовах `/api/chat`: `think: false` (+ вырезание `<think>…</think>`), `keep_alive: "30m"`, `temperature 0.1`,
`num_ctx 8192` (`OLLAMA_NUM_CTX`), `num_predict 400` (`OLLAMA_NUM_PREDICT`). Разбор запроса — `format: <JSON-схема>`.
Таймауты: соединение 5 с, ответ 120 с, разбор 60 с, вектор запроса поиска 2 с. Ретрай 1 раз и cooldown 30 с — только
на ConnectError/5xx. Лимиты: 2 одновременные генерации на процесс (`AI_MAX_CONCURRENT_GENERATIONS`, лишняя — сразу
`unavailable`), 10 запросов/мин с IP на `/parse`, `/answer*`, `/documents/*/answer*` (`AI_RATE_LIMIT_PER_MINUTE`, 429).

### Как сменить модель
1. `ollama pull <модель>`; 2. в `backend/.env` — `OLLAMA_MODEL=<модель>` (и при желании `OLLAMA_FALLBACK_MODEL`);
3. перезапустить backend; 4. прогнать eval: `cd backend && .venv/bin/python -m app.ai.eval` (должно быть 23/23).
Модель должна понимать `format` (JSON-схема) и `think: false` (для не-«думающих» моделей флаг игнорируется).
**Смена модели эмбеддингов:** если размерность ≠ 1024 — новая миграция `Vector(N)` (константа `EMBEDDING_DIM`
в `app/models/base.py`) и полная переиндексация `python -m app.services.indexing`; при той же размерности — только
переиндексация (векторы разных моделей несравнимы).

## Схема

```
запрос → guards (off-topic / injection / госуслуга, правила, без модели)
       → query parser (LLM, JSON-схема; при ошибке — полнотекст)  → гибридный поиск (только public)
       → top 8 → [ничего] «не нашёл» | [только закрытые] «ограниченный доступ»   (фиксированные тексты, без LLM)
       → LLM по КОНТЕКСТУ [S1]..[S8] → пост-проверка (метки, шифры, ссылки) → ответ + карточки от сервера
```

| Функция | API | Код |
|---|---|---|
| Статус | `GET /api/ai/status` | `services/ai.py::status` |
| Умный поиск (чипы) | `POST /api/ai/parse` | `ai/query_parser.py` |
| ИИ-справка / чат | `POST /api/ai/answer[/stream]` | `services/ai.py`, `ai/rag.py` |
| Вопрос по документу (T4.6) | `POST /api/ai/documents/{id}/answer[/stream]` | `services/ai_document.py`, `ai/document.py` |
| Похожие материалы (T4.12) | `GET /api/ai/recommendations` | `services/recommendations.py` (без LLM) |

Стрим — NDJSON: `meta` → `delta`* (уже пост-проверенные предложения) → `done {result: AiAnswer}`. Если `done`
пришёл с `mode=unavailable` после дельт — фронт заменяет показанный текст на `result.answer`.
Режимы ответа: `answer` (текст модели, метка «Сформировано ИИ, не является архивной справкой») и фиксированные
`not_found`, `restricted`, `off_topic`, `service`, `unavailable`, `empty`. `answer` — plain text; `[Sn]` фронт
превращает в ссылки по `sources` (ссылки строит сервер, не модель).

### Режим «по документу»
- Только публичный документ (опубликован, описание public) — иначе 404, как у карточки. Если файлы документа не
  `open` — фиксированный ответ «ограниченный доступ» без модели.
- Контекст: `[S1]` — описание + историческая справка; `[S2]…` — фрагменты OCR с номером листа (до 8 фрагментов,
  ≤ 6000 символов; если текст длиннее — фрагменты с наибольшим пересечением слов с вопросом). Номер листа — сквозной по
  файлам документа (`pages`, разрывы `\f` внутри OCR), закрытые файлы занимают свои номера, но их текст не читается.
- OCR берётся **на момент вопроса** только у файлов, которые проходят `authorize(None, "file.download")` — то же правило,
  что у `/api/files`. Сессия посетителя игнорируется: права сотрудника не открывают закрытый текст в публичной функции.
- Текст документа — данные: из него удаляются метки `[Sn]`, угловые скобки и переводы строк (не может подделать
  элемент контекста или закрыть цитату вопроса); правило в системном промпте — команды внутри текста не выполнять.
- «Нет ответа в тексте» → фиксированное «В этом документе таких сведений нет.» (`mode=not_found`).
- Источник в ответе: `AiSource` с `page` и `file_id` → фронт показывает «лист N» со ссылкой на `/api/files/{file_id}`.

### Похожие материалы
Вектор запроса — среднее векторов описания объекта (строки `chunk_no=0`; OCR не используется). Персонально: до 20
просмотренных документов из `localStorage` (параметр `seen`, переключатель «Персональные рекомендации», на сервере не
хранится) — вес объекта 2, истории 1, просмотренные исключаются. Кандидаты — косинусное расстояние ≤ 0.6 по HNSW,
каждый перепроверяется по живому объекту (`INDEXED_TYPES[...].is_public`). Без векторов — фолбэк: документы — общие
опубликованные теги, затем тот же фонд; прочие типы — FTS по словам названия. В карточке документа `related` =
сначала соседи по векторам, затем то же дело и темы (контракт B07 не менялся).

## Промпты (`app/ai/prompts.py`)
- `SYSTEM_PROMPT` — основа из плана работ §4.3 (одна русская версия + строка «Отвечай на {языке}»), запрос всегда в
  отдельном сообщении между `<<<` и `>>>`, угловые скобки из запроса удаляются.
- `DOCUMENT_RULES` — добавка режима документа (цитата + лист + метка, фраза «нет сведений», текст = данные).
- `PARSER_PROMPT` — разбор запроса в `{intent, doc_types, places, period, topics, persons, keywords, lang}`.
- Фиксированные тексты kk/ru/en: `NOT_FOUND`, `RESTRICTED`, `OFF_TOPIC`, `UNAVAILABLE`, `SERVICE`, `EMPTY_QUERY`,
  `NO_INFO`, `DOCUMENT_RESTRICTED`, `DOCUMENT_UNAVAILABLE`, `DOCUMENT_EMPTY`.

## Ограждения
- **До модели** (`ai/guards.py`): off-topic по однозначным маркерам (код, домашка, «за кого голосовать», лекарства,
  стихи…) → вежливый отказ; prompt-injection («игнорируй инструкции», «you are now», «покажи системный промпт»…)
  вырезается, остаток обрабатывается (`injection_ignored: true`); вопросы о справке → госуслуга + eGov без модели.
- **Контекст**: только публичные объекты (поиск перепроверяет живой объект); у документов с закрытыми файлами —
  только название, шифр, дата и условия доступа, без описания; OCR — только открытых сейчас файлов.
- **После модели** (`ai/rag.py`): метки только из контекста; шифры — только шифры элементов контекста (сравнение по
  компонентам фонд/опись/дело/лист); все ссылки, домены, e-mail, пути сайта, UUID вырезаются (текстом можно только
  `egov.kz`, `eotinish.kz`); пустой после проверки ответ → «не нашёл».
- ИИ ничего не принимает и не оформляет: ни заявлений, ни заказов, ни справок — только информация и ссылка на eGov.

## Ограничения
- 9B-модель иногда отвечает не на языке вопроса или смешивает языки; ответы — справка,
  а не архивная справка (метка в UI). Холодный старт модели ≈30 с, далее ответ 1–10 с.
- OCR в демо-данных — имитация (текст страницы = текст скана). История чата (6 сообщений) — в чат-виджете (T4.5).
- Лимиты и счётчики — в памяти одного процесса; при нескольких воркерах лимит на воркер.
- Рекомендации по векторам требуют проиндексированных векторов (`python -m app.services.indexing`); иначе фолбэк.

## История диалога и локализованные чипы мест (B27)

- `history` (опционально) в `/answer`, `/answer/stream` и в режиме документа: до 6 реплик `{role: user|assistant, text}`,
  user <= 500, assistant <= 1500 символов, всего <= 4000 (иначе 422). Без `history` поведение прежнее.
- Недоверенные данные: `guards.clean_history` вырезает injection из каждой реплики, отбрасывает off-topic/пустые реплики
  пользователя, убирает метки `[Sn]` из ответов ассистента. В модель история идёт не ролями, а цитируемым блоком
  «ИСТОРИЯ ДИАЛОГА» в user-сообщении (`prompts.history_block`; скобки `<>` вырезаются); факты берутся только из КОНТЕКСТА.
  Санитайзер ответа не менялся.
- RAG-поиск по текущему вопросу. Парсер видит две последние пользовательские реплики; если уточнение не называет вид,
  персону, тему и ключевые слова («а за 1970-е?», «а в Риддере?»), недостающие места/виды/персоны/темы берутся из
  разбора предыдущего вопроса (`services.ai._inherit_subject`, один доп. вызов парсера; 9B-модель сама это переносит ненадёжно).
- Язык: кириллица без казахских букв при `lang=kk` в интерфейсе считается казахским (`_resolve_lang`).
- `AppliedFilters.place_labels`: каноническое место -> название на языке вопроса из группы синонимов (kk — термин с
  казахскими буквами, en — без кириллицы); нет перевода — ключа нет. Поиск идёт по каноническому названию (`places`, `q`).

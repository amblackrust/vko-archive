# Архитектурные решения

Формат: дата — решение — обоснование. Новые записи добавлять в конец.

## 2026-11-10 — B01: фундамент backend

1. **Поиск в PostgreSQL, без Elasticsearch/OpenSearch.** Полнотекст `tsvector` (конфиг `simple`,
   у Postgres нет казахского стеммера) + `pg_trgm` для опечаток + `pgvector` для семантики,
   слияние RRF. Для прототипа один Postgres проще развернуть и сопровождать; поиск позже
   выносится в OpenSearch за интерфейсом `SearchBackend`.

2. **Единая таблица индекса `search_entries`.** Строка = (object_type, object_id, lang, chunk_no):
   title, body, `tsv` (tsvector), `embedding` (vector), embedding_model. Один индекс на все типы
   (документы, фонды, страницы, филиалы, выставки, коллекции, новости) упрощает единый поиск
   и RAG; `chunk_no` — для длинных текстов (OCR открытых файлов). В индекс пишется только
   разрешённое (description_status = public, опубликованный контент). GIN по `tsv`,
   GIN trigram по `title`, HNSW (cosine) по `embedding`.

3. **Размерность эмбеддингов = 1024.** Получена фактическим запросом к локальной Ollama
   `POST /api/embed {"model": "bge-m3", "input": "тест"}` → длина вектора 1024
   (совпадает с `embedding_length` в `GET /api/tags`). Зафиксирована константой
   `EMBEDDING_DIM` в `backend/app/models/base.py` и в миграции `0001` (`vector(1024)`).
   `/api/health` при каждой проверке сверяет фактическую размерность с константой.
   Смена модели эмбеддингов = новая миграция колонки + переиндексация.

4. **Перечисления — VARCHAR + CHECK, не нативные PG enum.** Добавление значения — простая
   замена CHECK-ограничения в новой миграции. `doc_type`, `period`, `language`, `theme`
   оставлены строками без CHECK: справочники будут расширяться из админки/импорта.

5. **Иерархия каталога через FK с ON DELETE RESTRICT** (фонд → опись → дело → документ):
   удалить родителя с потомками нельзя. `documents.case_id` допускает NULL, чтобы черновик
   или импортированная запись могли существовать до привязки к делу.
   `documents.archive_code` (шифр) — отдельное уникальное поле; стабильный внутренний id — uuid.

6. **Общие поля контента** (`ContentMixin`): id uuid, slug (уникальный, nullable), created_at/
   updated_at, created_by, workflow_status (draft/review/needs_changes/approved/published/
   archived), version, translation_status (JSONB по языкам). Переводимые поля — JSONB
   `{"kk","ru","en"}`.

7. **Полиморфные связи без FK**: `digital_files.owner_type/owner_id`, `collection_items.item_type/
   item_id`, `related` в news/memorial_dates, `workflow_history`/`audit_logs` object_type/id.
   Целостность таких ссылок проверяет сервисный слой. Явные M2M: document_tags (тематика),
   document_categories, person_documents, event_documents.

8. **Цикл FK users ↔ branches ↔ digital_files** разорван `use_alter`: FK `users.branch_id` и
   `branches.photo_file_id` создаются в миграции отдельным `create_foreign_key` после таблиц.

9. **Добавлены сущности сверх таблицы §2**: `search_entries` (см. п.2) и `notifications`
   (колокольчик согласования, T6.12), `workflow_history.snapshot` (JSONB для diff версий),
   `audit_logs.actor` (логин для неудачных входов). Модели личного кабинета посетителя (T5.18)
   и статистики просмотров не создавались — их пачки добавят новой миграцией.

10. **Синхронный SQLAlchemy + psycopg 3.** Проще и надёжнее для прототипа; FastAPI выполняет
    sync-эндпоинты в threadpool.

11. **`/api/health`** всегда отвечает (Ollama недоступна → компонент `unavailable`, общий статус
    `degraded`, HTTP 200). HTTP 503 — только если недоступна БД. В ответ не попадают строки
    подключения: только имя класса исключения. Проба эмбеддингов делает реальный
    `/api/embed` с отдельным таймаутом 30 с (первый вызов загружает модель).

12. **Тесты на реальной БД.** pytest использует отдельную базу (`TEST_DATABASE_URL`, по умолчанию
    `<имя>_test` на том же сервере), создаёт её при необходимости и прогоняет миграции с нуля;
    тест `test_models_match_migrations` ловит расхождение моделей и миграций.

13. **Порт PostgreSQL 5432** на хосте был свободен — используется стандартный
    (переопределяется `POSTGRES_PORT` в `.env`).

## 2026-11-10 — B01: исправления по ревью

14. **Собственный уровень доступа у файла.** `digital_files.access` (FileAccess, NOT NULL,
    по умолчанию `needs_review`) — файл, привязанный к экспонату/новости/и т.п., не может
    «унаследовать» открытость от владельца и обойти `documents.file_access`.
    **Правило для `GET /api/files/{id}` (B05/B12):** файл отдаётся, только если
    (а) `digital_files.access` разрешает выдачу этому пользователю **И**
    (б) если `owner_type = 'document'`, то документ существует и его `file_access`
    (и публикация/`description_status`) тоже разрешает. Нет владельца, владелец не найден,
    нет прав или `needs_review` для анонима → **404** (не 403, чтобы не раскрывать существование).
    Проверка — в services через `authorize(user, "file.download", file)`.

15. **`/api/health` публичный → защищён от DoS.** Результат проб Ollama/эмбеддингов кешируется
    в памяти на `HEALTH_CACHE_TTL_SECONDS` (60 с) под `threading.Lock` (одна проба на TTL,
    без «стада»), таймаут проб `HEALTH_PROBE_TIMEOUT_SECONDS` = 3 с (заменяет п.11 про 30 с).
    Имена моделей в ответ не попадают (только статус и `dim=`). Первая проба при «холодной»
    bge-m3 может дать `unavailable` на 60 с — допустимо.

16. **Ограничения схемы (миграция 0002):** номер фонда уникален в пределах архива
    (`UNIQUE NULLS NOT DISTINCT (branch_id, number)`); email уникален без учёта регистра
    (уникальный индекс `lower(email)` вместо регистрозависимого), сервисы хранят email
    нормализованным (strip + lower); CHECK `date_from <= date_to`, `month 1..12`, `day 1..31`,
    `lat -90..90`, `lng -180..180`. PostgreSQL слушает только `127.0.0.1`.

## 2026-11-10 — B12: авторизация, права, согласование, журнал

17. **Сессия админки — JWT (HS256, PyJWT) в httpOnly + Secure + SameSite=Strict cookie `vko_session`.**
    Ключ `JWT_SECRET` только из env (≥ 32 символов, плейсхолдер `change_me…` отклоняется;
    `make env` генерирует случайный). Неактивность 30 мин = `exp`, токен перевыпускается на
    каждом запросе (скользящее окно), но не дольше 12 ч от входа (`auth_time`). Смена пароля
    инвалидирует остальные сессии (claim `pwv` = `password_changed_at`). Деактивация
    пользователя действует сразу (пользователь читается из БД на каждом запросе).
    Ограничение: logout очищает cookie, но не отзывает токен на сервере (нет таблицы сессий,
    чтобы не трогать схему); украденный токен живёт ≤ 30 мин бездействия.
18. **CSRF — токен внутри JWT** (claim `csrf`), фронт получает его в ответе login/`me` и в
    читаемой cookie `vko_csrf` и шлёт в `X-CSRF-Token` на POST/PUT/PATCH/DELETE; сравнение
    `hmac.compare_digest`. Плюс SameSite=Strict.
19. **Пароли — argon2id (argon2-cffi)**, длина 10–256, неизвестный email проверяется против
    фиктивного хеша (одинаковое время ответа). 5 неудач подряд → блок 15 мин.
    *Изменено по ревью (п.25): при входе блокировка больше не отдаёт 429.*
20. **Права — строки `module.action`** (каталог в `services/authz.PERMISSIONS`), матрица в БД
    (`permissions`, `role_permissions`), по умолчанию — `DEFAULT_ROLE_PERMISSIONS`, применяется
    только при создании роли. Главный админ обходит матрицу; `roles.manage` (правка матрицы)
    вне матрицы — только главный админ, чтобы никто не выдал себе права и не запер его.
    Филиальная область: если все роли пользователя из {branch_admin, archivist} и задан
    branch_id (branch_admin — всегда), объект должен принадлежать его филиалу; филиал объекта
    каталога выводится из иерархии case → inventory → fund.branch_id (`documents.branch_id`
    синхронизируется при сохранении через `save_with_version`).
21. **Отказ в доступе журналируется** (`result=denied`) отдельным коммитом после rollback
    запроса. Для `file.download` отказ → 404 (DECISIONS п.14), для остального → 403.
22. **Workflow:** submit (draft/needs_changes→review), return (review/approved→needs_changes,
    комментарий обязателен), approve (review→approved), publish (approved→published),
    archive (published/approved→archived), restore (archived→draft). Оптимистическая
    блокировка `UPDATE … WHERE version=:v` → 409 `version_conflict`. История = снимки в
    `workflow_history.snapshot`, diff считается между соседними снимками. Публикация не
    меняет `file_access`/`digital_files.access`.
23. **Миграция не понадобилась:** модели B01 покрыли все поля; номер `0004_*` не занят.

## 2026-11-10 — B12: исправления по ревью

24. **Назначение ролей — отдельное действие `users.assign_role`** (obj = `authz.RoleChange(target, role)`,
    вне матрицы, выводится из `users.manage`). Не главный админ не выдаёт и не снимает `super_admin`
    и не трогает пользователей с ролью `super_admin`. Никто (включая главного админа) не меняет
    собственные роли (`users.assign_role`) и собственный статус/учётку через `users.manage`
    (блокировка/деактивация себя) — свой пароль меняется через `/auth/password`, остальное — CLI.
25. **Вход неотличим для любой учётки:** argon2 verify выполняется всегда до любых проверок; неизвестный
    email, неверный пароль, заблокированная и неактивная учётка → одинаково 401 `invalid_credentials`
    без Retry-After (и на 5-й неудаче). Фронт показывает общий текст «неверный email или пароль; после
    5 неудачных попыток вход блокируется на 15 минут». **Компромисс:** зная чужой email, можно
    заблокировать эту учётку на 15 мин (DoS); для демо допустимо, следующий этап — лимит по IP/капча
    на прокси. 429 `account_locked` + Retry-After остаётся только у `/auth/password`.
26. **`/auth/password` делит счётчик с входом:** неверный текущий пароль увеличивает `failed_logins`,
    5-я неудача блокирует учётку (429) — и смену пароля, и вход. Успешная смена обнуляет счётчик.
27. **Модульное право на переходах workflow:** кроме `workflow.*` нужен `<module>.edit` для `submit`
    (отправляющий отвечает за содержимое) и `<module>.view` для return/approve/publish/archive/restore
    (проверяющему достаточно видеть объект). Модуль — из `workflow.WORKFLOW_OBJECTS`
    (catalog/branches/content), филиал объекта учитывается через `authorize()`.
28. **Фоновые запросы не продлевают сессию:** заголовок `X-Background: 1` (или эндпоинт с
    `BackgroundUser`, сейчас `GET /notifications`) — аутентификация без перевыпуска cookie.
29. **`OptionalUser`** передаёт реальный метод; на небезопасном методе без верного CSRF запрос
    обслуживается как анонимный (не 403): публичный эндпоинт и так доступен анониму, а права
    сотрудника без CSRF не применяются. Без `JWT_SECRET` — тоже аноним; вне `APP_ENV=development`
    приложение без `JWT_SECRET` не стартует (RuntimeError в `create_app`). CSRF сравнивается байтами.
30. **Журнал:** при входе с неизвестным email `actor` пуст (введённое значение может быть паролем
    или чужими ПДн); отказы `file.download` для анонимов не журналируются (битые ссылки, боты).
    REVOKE UPDATE/DELETE на `audit_logs` не сделан: приложение подключается владельцем таблиц
    (REVOKE для владельца ненадёжен), а FK `audit_logs.user_id ON DELETE SET NULL` требует UPDATE —
    следующий этап: отдельная роль БД для приложения + журнал без FK/с триггером append-only.
31. **Оговорки (демо):** `branch_scoped` выключается, если у пользователя есть роль вне
    {branch_admin, archivist} (вторая роль расширяет область до всего архива); разделение
    обязанностей не обеспечивается — пользователь с правами submit и review/publish может провести
    свой материал сам; `client_ip` = адрес TCP-пира, за обратным прокси нужен доверенный
    `X-Forwarded-For` (uvicorn `--proxy-headers --forwarded-allow-ips`); 404 на несуществующий
    объект отдаётся до проверки прав (сотрудник без прав может узнать, существует ли UUID —
    допустимо, UUID неугадываемы).

## 2026-11-10 — B05: индексация, единый поиск, выдача файлов

32. **Фасеты не денормализуются в `search_entries`** (миграция не нужна). Поиск берёт кандидатов
    из индекса (FTS / trigram / vector, до 200 на метод), сливает RRF (k = 60), затем загружает
    живые объекты и **повторно проверяет публичность** (`indexing.INDEXED_TYPES[t].is_public`):
    устаревшая строка индекса не может показать скрытый объект ни в выдаче, ни в счётчиках,
    ни в фасетах. Фасеты (type, doc_type, period, branch) считаются в Python по проверенному
    набору, дизъюнктивно (каждое измерение — со всеми фильтрами, кроме своего). Ограничение:
    `total` — не больше суммы кандидатов (≈ 600), для каталога с фильтрами — `/api/catalog` (B06).
33. **Что индексируется:** документ — `published` И `description_status = public`; фонд, страница,
    филиал, выставка, коллекция, новость — `published`. OCR — только файлов, которые может
    скачать аноним (`authorize(None, "file.download", …)`), отдельными чанками (`lang = "und"`,
    `chunk_no ≥ 1`, ≤ 1200 символов). Персоны/события/НПА пока не индексируются.
34. **Синхронность:** `workflow.save_with_version` (все сохранения и переходы) вызывает
    `indexing.reindex_object` в той же транзакции — снятие с публикации / do_not_publish удаляет
    строки до коммита. Эмбеддинги — после ответа (`BackgroundTasks` в роутере переходов) или
    командой `python -m app.services.indexing`; при неизменном тексте вектор сохраняется.
35. **Запрос:** конфиг `simple`; лексемы с префиксом `:*`, слова ≥ 6 букв усекаются на 2 буквы
    (замена стеммера для ru/kk); синонимы — OR-альтернативы (многословные — фразой `<->`);
    сначала все слова (AND), при пустом результате — любое (OR); короткий стоп-лист ru/kk/en.
    Trigram — `word_similarity` запроса к заголовку (`<%`, порог 0.6). Вектор — косинусное
    расстояние ≤ 0.5 (bge-m3, подобрано на демо-каталоге: релевантные 0.40–0.49, мусорные
    запросы ≥ 0.57). Нет Ollama → `semantic: false`, поиск FTS + trigram; после ошибки
    эмбеддинг запроса не пробуется 30 с.
36. **Сниппеты** — `ts_headline` по индексированному (публичному) тексту с маркерами из
    Private Use Area, затем HTML-экранирование и замена маркеров на `<mark>`; фронт может
    вставлять `snippet` как HTML.
37. **Ссылки в выдаче строит сервер** (`href` без префикса локали): `/catalog/documents/{id}`,
    `/catalog/funds/{id}`, страницы — `/about/history`, `/about/structure`, `/contacts`,
    `/compliance` (иначе `/pages/{key}`), `/branches/{slug}`, `/exhibitions/{slug}`,
    `/memory/collections/{slug}`, `/news/{slug}`. Пути файлов в ответах не бывает.
38. **`GET /api/files/{id}` — 404, не 403** (п.14 важнее формулировки T3.7 в PLAN.md: не раскрываем
    существование). Путь файла резолвится внутри `STORAGE_DIR` (выход за пределы / нет файла → 404
    + лог). `nosniff`; публичные файлы `Cache-Control: public, max-age=3600`, выданные по правам
    сотрудника — `private, no-store`; HTML/SVG/XML — `attachment` + CSP `sandbox`. Файлы
    не-документов отдаются, только если владелец `published` (и `access = open`).
39. **Стартовые синонимы** (12 групп из PLAN.md §1) пишет команда индексации, только если таблица
    `synonyms` пуста — правки из админки не перетираются.

## 2026-11-10 — B05: исправления по ревью

40. **`/api/files`: inline только по allowlist.** mime нормализуется (`split(";")[0].strip().lower()`); inline —
    `image/png|jpeg|webp|gif`, `application/pdf`, `text/plain`, `audio/*`, `video/*`, остальное — `attachment`.
    CSP `default-src 'none'; style-src 'unsafe-inline'; sandbox` — на всех ответах. Заменяет часть п.38 про HTML/SVG/XML.
41. **Кеш файлов:** публичные — `public, no-cache` + ETag/304 (304 только после проверки прав), по правам сотрудника —
    `private, no-store`. Заменяет `max-age=3600` из п.38: закрытие файла действует сразу.
42. **Текст документа в индексе** включает названия фонда/дела и тегов, только если они `published`. Сохранение
    фонда/описи/дела через `save_with_version` синхронно переиндексирует их документы (та же транзакция).
43. **OCR-чанки хранят `file_id`** (миграция 0004) и перепроверяются при поиске: `authorize(None, "file.download", file)`
    на лету; чанк без `file_id` не используется.
44. **Поиск сознательно игнорирует пользователя:** `/api/search` одинаков для всех, сотрудники видят только публичное

    Starlette отразил бы любой origin), методы GET/POST/PUT/PATCH/DELETE, заголовки Content-Type, X-CSRF-Token,
    X-Background, X-Request-ID; expose — Retry-After, X-Request-ID.
82. **CSP фронта** (`next.config.ts`): `script-src 'self' 'unsafe-inline'` (+`'unsafe-eval'` только в dev) — App Router
    вставляет инлайн-скрипты гидратации, nonce требует middleware и делает все страницы динамическими (ломает ISR).
    Защита от XSS — экранирование React + `clean_html` на сервере (п.71); CSP закрывает внешние источники: img — API и
    `tile.openstreetmap.org`, connect — API и `nominatim.openstreetmap.org`, object/frame — `'none'`,
    `frame-ancestors 'none'`, `form-action 'self'`. Origin API берётся из `NEXT_PUBLIC_API_URL` при сборке. HSTS —
    только prod-сборка при `https://` в `NEXT_PUBLIC_SITE_URL`. Геолокация разрешена себе (маршрут от меня).
83. **Лимиты запросов.** Вход сотрудника — 20/мин на IP (429 + Retry-After) поверх блокировки учётки; вход/регистрация
    посетителя (B21) и ИИ (п.64) — как были. Общий лимит на весь API не вводится: SSR Next ходит в API с одного адреса.
    **Ограничение прототипа:** счётчики в памяти процесса — при нескольких воркерах uvicorn лимит считается на воркер,
    после рестарта обнуляется; для продакшена — общий счётчик (Redis) или лимит на обратном прокси.
    За обратным прокси `client_ip` — адрес прокси (п.31): все входы попадут в одну корзину лимита. Включать
    `--proxy-headers --forwarded-allow-ips=<прокси>` или ограничивать вход на самом прокси.
84. **Регистрация посетителя по-прежнему отвечает `email_taken` (не закрыто).** Одинаковый ответ без раскрытия
    занятости невозможен, пока регистрация сразу открывает сессию: для свободного e-mail сессия есть, для занятого — нет.
    Нужна смена контракта: `register` → всегда 202 «проверьте почту» без сессии (+ письмо-подтверждение) и правка
    формы `components/cabinet/auth-forms.tsx` — фронт вне зоны B24 (параллельно B23). Смягчение сейчас: лимит 5
    регистраций/мин на IP. Решение — за оркестратором.
85. **Тестовый журнал.** Тесты не удаляют строки `audit_logs` (триггер п.79); тестовая БД пересоздаётся каждой сессией pytest.

## 2026-11-11 — Оркестратор: решение по п.84

86. **Раскрытие занятости e-mail при регистрации посетителя — принятый риск прототипа.** Почтовой рассылки нет,
    поэтому схема «всегда 202 + письмо-подтверждение» сделала бы регистрацию нерабочей. Смягчение: лимит 5 регистраций/мин
    на IP, вход посетителя всегда отвечает одинаково (401 invalid_credentials). Для продакшена — подтверждение e-mail
    и одинаковый ответ register (следующий этап).
## 2026-11-11 — B24: исправления по ревью

87. **next/image для файлов API** (`next.config.ts` `images`): `remotePatterns` — только origin API и путь
    `/api/files/**`, форматы AVIF/WebP. Оптимизатор Next запрашивает файл с сервера без cookie, т.е. как аноним:
    закрытый файл получит 404 и в кэш оптимизатора не попадёт. CSP не менялась (`/_next/image` — `'self'`).

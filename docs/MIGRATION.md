# План миграции со старого сайта e-arhiv.vko.gov.kz

## Почему автоматический сбор не делался

- **Наличие сайта не означает разрешения копировать его содержимое.** Тексты, документы и фотографии принадлежат архиву, а часть материалов может иметь ограничения на публикацию. Решение о переносе принимает заказчик. Это дополнение к ТЗ.
- **Объём и формат определяются с заказчиком** (раздел 11 ТЗ). Без выгрузки неизвестно, что именно есть на сайте, в каком виде и что из этого можно публиковать.
- Парсинг страниц дал бы текст без связей и прав доступа: фонды, описи, дела и документы пришлось бы восстанавливать вручную, а статусы доступа нельзя угадать.

Поэтому проект работает на данных из `info/` и синтетических данных, а перенос выполняется по выгрузке от заказчика.

## Что переносим

Страницы, контакты, филиалы, новости, фонды, описи, дела и документы (с цифровыми копиями), медиа, перечень НПА.

## Процесс

1. **Выгрузка от заказчика.** Таблицы (CSV/XLSX) по фондам, описям, делам и документам; файлы-оригиналы; тексты страниц и новостей; список НПА. Заказчик указывает, что публиковать нельзя.
2. **Сопоставление полей.** Колонки выгрузки привязываются к полям нашей модели по таблице ниже. Спорные поля фиксируются с заказчиком.
3. **Пробный импорт.** Через существующий импорт в админке (`/admin/import`): сначала предпросмотр (ничего не записывается), затем применение на тестовой копии. Импорт создаёт только черновики: `workflow_status=draft`, `description_status=needs_review`, `file_access=needs_review`, поэтому ничего не публикуется само. Недостающие фонды, описи и дела создаются как черновики. Для «всё или ничего» есть режим `atomic`.
4. **Сверка.** Количество фондов, описей, дел и документов в выгрузке и в системе, связи по номерам фонд/опись/дело, шифры без дублей, наличие файлов у документов с цифровой копией. Выборочная проверка текстов и дат.
5. **Журнал ошибок.** Отчёт предпросмотра и применения (строки с ошибками и причины) выгружается из ответа импорта и передаётся заказчику; исправленные строки импортируются повторно. Повторный импорт того же файла ничего не меняет.
6. **Откат.** Перед боевым импортом делается резервная копия (`make backup`). Импортированные документы остаются черновиками, поэтому их можно удалить или исправить до публикации. При проблеме с партией восстанавливается копия базы.
7. **Согласование и публикация.** Сотрудники проверяют черновики, задают доступ к файлам и публикуют через обычный процесс согласования. Переводы kk/en проходят вычитку.

Ограничение: массовый импорт реализован только для документов. Страницы, новости, филиалы, НПА и файлы вносятся через админку (или отдельным скриптом по согласованному формату).

## Сопоставление

| Раздел старого сайта | Сущность проекта | Способ переноса |
|---|---|---|
| Страницы («Об архиве», структура, история) | `Page` | Вручную через админку |
| Контакты | `Page` (раздел «Контакты») и настройка `contacts` в `site_settings` | Вручную через админку |
| Филиалы и адреса | `Branch` | Вручную; координаты уточняются у заказчика |
| Новости | `News` | Вручную через админку |
| Фонды | `Fund` | Импорт (колонка `fund_number`), недостающие создаются черновиками |
| Описи | `Inventory` | Импорт (`inventory_number`) |
| Дела | `Case` | Импорт (`case_number`) |
| Документы (описание) | `Document` | Импорт CSV/XLSX по шифру `archive_code` |
| Цифровые копии | `DigitalFile` | Загрузка в админке, доступ задаётся вручную |
| Фотографии, медиа | `DigitalFile` (обложки выставок и новостей, экспонаты) | Загрузка в админке |
| НПА | `LegalAct` | Вручную через админку |
| Памятные даты | `MemorialDate` | Вручную или скриптом по выгрузке |

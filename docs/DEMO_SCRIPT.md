# DEMO_SCRIPT — сценарий защиты (T8.3)

Источник: плана работ §6 (сценарии проверки) и §7 (сценарий защиты). В базе три вида данных
([DATA_SOURCES.md](DATA_SOURCES.md)): реальные перечни фондов архива (только названия), подлинные изображения
с Wikimedia Commons в выставках, «Архиве памяти» и фонде «ОИ-1» (с автором и лицензией; в фонды архива не входят)
и вымышленные документы шести демо-фондов (бейдж «Демо-запись»). Персональных данных граждан на сайте нет.
Длительность: 12–15 минут.

## 0. Подготовка (за 30 минут до выступления)

```bash
make dev                                   # PostgreSQL, миграции, backend :8000, frontend :3000
cd backend
.venv/bin/python -m seed                   # данные из info/, открытые материалы и демо-каталог (идемпотентно)
.venv/bin/python -m app.services.indexing  # поисковый индекс и эмбеддинги (нужна Ollama)
ollama list                                # qwen3.5:9b и bge-m3 на месте
curl -s localhost:8000/api/health          # db / ollama / embeddings = ok
```

- Прогреть модель одним запросом в поиске (первый ответ после простоя медленнее; `keep_alive: 30m`).
- Открыть заранее вкладки: `/ru`, `/ru/admin` (отдельное окно, выйти из сессии), старый сайт архива.
- Тёмная тема и мобильный режим (DevTools, 375 px) — готовы к показу.
- Автопроверка перед показом: `cd frontend && npm run e2e` (поднимает отдельные стенд и БД, ничего не портит).

## 1. Учётные записи

Демо-аккаунты сотрудников (плана работ §5) создаёт CLI; **учётных записей в seed нет**, их создают один раз:

```bash
cd backend
while IFS='|' read -r email role name; do
  VKO_USER_PASSWORD='Demo-Pass-2026!' .venv/bin/python -m app.cli create-user --email "$email" --role "$role" --full-name "$name"
done <<'USERS'
superadmin@demo.kz|super_admin|Главный администратор
siteadmin@demo.kz|site_admin|Администратор сайта
editor@demo.kz|editor|Редактор
archivist@demo.kz|archivist|Сотрудник архива
moderator@demo.kz|moderator|Модератор
analyst@demo.kz|analyst|Аналитик
USERS
# Администратор филиала привязывается к филиалу: id Риддерского филиала берём из /api/admin/branches
VKO_USER_PASSWORD='Demo-Pass-2026!' .venv/bin/python -m app.cli create-user \
  --email branch.ridder@demo.kz --role branch_admin --branch-id <UUID филиала branch-ridder> --full-name "Администратор Риддерского филиала"
```

| Роль | Логин | Пароль | Что показывать |
|---|---|---|---|
| Главный администратор | `superadmin@demo.kz` | `Demo-Pass-2026!` | всё: роли и права, журнал, настройки |
| Администратор сайта | `siteadmin@demo.kz` | `Demo-Pass-2026!` | страницы, пользователи, контент |
| Редактор | `editor@demo.kz` | `Demo-Pass-2026!` | создаёт материал, отправляет на согласование |
| Сотрудник архива | `archivist@demo.kz` | `Demo-Pass-2026!` | каталог, ИИ-инструменты |
| Администратор филиала | `branch.ridder@demo.kz` | `Demo-Pass-2026!` | только Риддерский филиал |
| Модератор | `moderator@demo.kz` | `Demo-Pass-2026!` | согласование и публикация |
| Аналитик | `analyst@demo.kz` | `Demo-Pass-2026!` | только чтение: аналитика |

Пароль — **демонстрационный**, только для локальной базы; для любого публичного стенда сменить (`/ru/admin` →
смена пароля) или создать учётки заново. Пароли не пишутся в журнал действий и логи (проверено тестами).
Тот же пароль подставляет `npm run e2e` (переменная `E2E_DEMO_PASSWORD`, изолированная БД `vko_archive_e2e`).

Посетителю (личный кабинет, `/ru/cabinet`) готовых учёток нет: регистрация открытая, пример — любой `*@demo.kz`.

## 2. Ход демонстрации

Время — ориентир. «Говорить» — тезис вслух, «Показать» — действие на экране.

### Шаг 1. Старый сайт: «найдите фото завода 60-х» (1 мин)
- **Показать:** на действующем сайте архива найти фото; считать клики/время (по ТЗ — нужны разделы, поиск по
  тексту, нет фильтров по типу/периоду).
- **Говорить:** «Обычный посетитель не знает, что такое фонд и опись, и уходит ни с чем».
- **Избегать:** критиковать конкретных людей; называть цифры, которых не замерили.

### Шаг 2. Новый сайт: тот же запрос (2 мин)
- **Показать:** `/ru/search`, набрать «фото цеха 1950-х». Появляются чипы фильтров «Тип: Фотография»,
  «Период: 1950-е», найденные документы и ИИ-справка со ссылками на источники. Нажать чип — фильтр снимается.
- **Говорить:** «Запрос разбирается локальной моделью; ссылки на документы строит сервер по найденным записям,
  модель их не придумывает».
- **Избегать:** запросов про «завод» — в демо-данных он назван «комбинатом»/«цехом» (ответ «не нашёл» уместен
  только на шаге 5); не ждать ответ молча, пока модель «думает» — рассказывать про архитектуру.

### Шаг 3. Тот же запрос на казахском (1 мин)
- **Показать:** переключатель `KZ` в шапке; запрос «1950 жылдардағы цех фотосуреттері». Интерфейс и ответ — на
  казахском, фильтры сохранились.
- **Говорить:** «Переводы части контента машинные или отсутствуют — это помечено в UI».
- **Избегать:** обещать полноту казахских текстов (kk/en строки — рабочий перевод, нужна вычитка).

### Шаг 4. Документ и «Спросить об этом документе» (2 мин)
- **Показать:** карточка «Приказ № 31 о пуске цеха обогащения (ДЕМО)» (`/ru/catalog/documents/…`): шифр, дерево
  фонд → опись → дело, просмотр копии, зум, листание. Кнопка «Когда выдан документ?» → ответ с пометкой
  «Сформировано ИИ, не является архивной справкой» и указанием листа.
- **Говорить:** «ИИ отвечает только по открытому описанию и распознанному тексту этого документа».
- **Избегать:** вопросов не по документу («что было в 1960-м?») — получите «нет сведений» (это нормально, но
  сорвёт ритм); показывать OCR: в текущем окружении он не работает (нет Tesseract/vision-модели).

### Шаг 5. Негатив (2 мин)
- **Показать:** (а) «метро в Усть-Каменогорске» — ИИ не выдумывает, источников нет; (б) карточка
  «Протокол № 5 заседания профкома (ДЕМО)» (ограниченный доступ) — файла нет, блок «Условия доступа» и ссылка
  на eGov.kz; прямая ссылка на файл → 404; (в) в чате/поиске «напиши код на python» — вежливый отказ.
- **Говорить:** «Доступ проверяется на сервере: карточка, файл, прямая ссылка, API. Закрытое не утекает даже в
  ответах ИИ и в индексе».
- **Избегать:** подсказывать публике настоящие закрытые идентификаторы; вводить реальные ФИО в поиск.

### Шаг 6. Обычная навигация (2 мин)
- **Показать:** выставка «Промышленное развитие Восточного Казахстана (ДЕМО)» → экспонат 6: зум, подпись,
  «К документу в каталоге»; хронология `/ru/memory/timeline`; карта филиалов `/ru/branches` → «Риддерский
  городской филиал» → «Использовать моё местоположение» (отказ → понятное сообщение), адрес «Усть-Каменогорск» →
  расстояние и ссылки 2GIS/Google/Яндекс; переключить тёмную тему; открыть мобильный режим (375 px).
- **Говорить:** «Координаты приблизительные и так помечены; карта на OSM без ключей, сбой тайлов не ломает
  страницу».
- **Избегать:** построения маршрута по адресу без интернета (геокодер внешний, Nominatim) — только ссылки на карты.

### Шаг 7. Госуслуга и прейскурант (1 мин)
- **Показать:** `/ru/services/state` → «Перейти на eGov.kz» и «e-Otinish» (внешние, в новой вкладке);
  `/ru/services/paid`.
- **Говорить:** «Здесь заявки не принимаются — только информация и переход на официальные сервисы. Форм, оплаты и
  отслеживания статуса нет по требованию заказчика».
- **Избегать:** называть сроки и цены — раздел помечен «ДЕМО», прейскуранта в исходных материалах нет.

### Шаг 8. Админка: редактор → модератор → публикация (3 мин)
Окна: два браузерных профиля или приватное окно для второй роли.
1. `editor@demo.kz` → «Контент сайта» → создать новость «ДЕМО …» → «На согласование». Показать, что по прямой
   ссылке `/ru/news/<slug>` — «Страница не найдена».
2. `moderator@demo.kz` → колокольчик уведомлений → «Вернуть» (комментарий обязателен) → редактор исправляет и
   отправляет снова → «Одобрить» → «Опубликовать». Страница стала доступна; в карточке — история версий.
3. `branch.ridder@demo.kz` → «Филиалы»: виден только Риддерский. Опубликованную карточку сначала «вернуть в
   работу» (снимается с сайта), поменять телефон, отправить на согласование. Чужой филиал по прямому URL/API → 403.
4. `superadmin@demo.kz` → «Журнал действий» (кто/что/когда, пароли не пишутся) и «Роли и права».
5. `analyst@demo.kz` → «Аналитика»: популярные запросы, запросы без результатов, ИИ-вывод (ФИО/e-mail маскируются).
6. `archivist@demo.kz` → «ИИ-инструменты»: анализ документа (даты, имена, места, теги) — поля применяются
   только после подтверждения сотрудником.
- **Говорить:** «Любая публикация идёт через согласование; права проверяются на сервере единым `authorize`».
- **Избегать:** ИИ-OCR скана — заявлен как **частично** (нет движка в окружении), показывать только анализ метаданных
  по готовому тексту; удалять объекты в живой базе; входить под редактором пока заблокирован вход (5 неверных
  паролей блокируют учётку на 15 минут; лимит входа — 20 в минуту с IP).

### Шаг 9. Локальная модель (30 с)
- **Говорить:** «Модель работает локально (Ollama): данные архива и запросы граждан никуда не уходят. Отказ модели
  не ломает сайт — поиск по словам и каталог продолжают работать».
- **Показать (по желанию):** `curl localhost:8000/api/health`; остановить Ollama → поиск даёт результаты, ИИ-блок
  сообщает «Не удалось получить ответ», кнопки вопросов к документу неактивны.

### Шаг 10. Таблица готовности и план развития (1 мин)
- **Показать:** `READINESS.md` — статусы «Реализовано / Частично / Имитация-макет / Следующий этап».
- **Говорить:** честно о границах (OCR, перевод kk/en, прейскурант, часть направлений «Архива памяти»,
  интеграции — «демонстрационные»).

## 3. Что нельзя показывать и говорить
- Любые «заявки», «заказ справки», «оплата» — их на сайте нет по ТЗ.
- Реальные ФИО и документы граждан: документы демо-фондов вымышленные и помечены «Демо-запись». Изображения
  выставок и «Архива памяти» — подлинные, из открытого источника; не называть их документами из фондов архива.
- Не выдавать мок за готовое: перечень «Имитация/макет» и «Частично» — в `READINESS.md`.
- Не трогать `backend/storage/`, не удалять базу перед показом; резервная копия: `make backup`.

## 4. Запасной план
| Сбой | Действие |
|---|---|
| Ollama не отвечает/долго | Показать поиск по словам и каталог; рассказать про fallback; запасная модель `qwen3.5:9b-q4_K_M` |
| Нет интернета | Карта без тайлов — работают адрес и ссылки; Nominatim недоступен — сообщение, ссылки на 2GIS/Google/Яндекс |
| Вход сотрудника заблокирован (429/401) | Подождать 15 мин или войти другой ролью; пересоздать учётку через CLI |
| Пустая выдача | Проверить индекс: `python -m app.services.indexing` |
| Сломалась демо-база | `docker compose up -d --wait db`, `alembic upgrade head`, `python -m seed`, индексация, пересоздать учётки |
